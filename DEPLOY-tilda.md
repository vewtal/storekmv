# Публикация сайта на Tilda

Сайт живёт как обычные HTML-страницы в этом репозитории, а публикуется вставкой
собранного кода в блок **T123 (HTML-код)** на Tilda. Домен storekmv.ru остаётся
на Tilda, DNS не трогаем.

## Шаг 0. Что должно быть сделано до вставки

Картинки отдаются с CDN публичного репозитория, поэтому ветка `main` должна
содержать актуальный `img/`:

```bash
git checkout main && git merge site-v2-strategy && git push origin main
```

Проверить, что CDN отдаёт файл (после push может занять пару минут):

```bash
curl -sI https://cdn.jsdelivr.net/gh/vewtal/storekmv@main/img/og-cover.jpg | head -1
# ожидается HTTP/2 200
```

## Шаг 1. Собрать блоки

```bash
python3 build-tilda.py
```

Скрипт кладёт в `dist/` по файлу на страницу и сам себя проверяет: не остались ли
относительные пути, ссылки на `.html` и теги документа. Пометка `ok` в каждой строке
вывода — сборка чистая, можно вставлять.

| Файл | Адрес страницы в Tilda |
|---|---|
| `dist/tilda-index.html` | `/` (главная) |
| `dist/tilda-warehouses.html` | `/warehouses` |
| `dist/tilda-equipment.html` | `/equipment` |
| `dist/tilda-investors.html` | `/investors` |
| `dist/tilda-privacy.html` | `/privacy` |

## Шаг 2. Создать страницы в Tilda

Для каждой строки таблицы:

1. Создать страницу, в настройках задать **адрес страницы** ровно как в таблице
   (`warehouses`, `equipment`, `investors`, `privacy`; у главной адрес пустой).
2. Добавить **единственный** блок: Библиотека блоков → «Другое» → **T123**.
3. Вставить содержимое соответствующего файла из `dist/` целиком.
4. Опубликовать.

**Блок должен быть один.** Код содержит собственные стили для `body`, ссылок и
заголовков и работает как самостоятельная страница. Если добавить сверху шапку или
снизу подвал Tilda, стили пересекутся и поедут оба макета.

## Шаг 3. Настройки страницы

Title, description и og:image в блок не входят — они задаются в настройках страницы
(Настройки → Facebook и SEO). Брать из `<head>` соответствующего исходного файла:

- **Главная** — title и description из `index.html`, строки 6–7.
- **og:image** — `https://cdn.jsdelivr.net/gh/vewtal/storekmv@main/img/og-cover.jpg`
  (1200×630, лежит в репозитории).
- **Favicon** — загрузить `img/favicon.png` в настройках сайта.

`robots.txt`, `sitemap.xml` и страницу 404 Tilda формирует сама. Одноимённые файлы из
репозитория на Tilda не используются — они остаются на случай переезда на свой хостинг.

## Шаг 4. Формы

Формы отправляют заявку POST-запросом в serverless-функцию `api/lead.js`. На Tilda
страница и функция живут на разных доменах, поэтому нужен отдельный проект Vercel
только под API — домен storekmv.ru при этом не затрагивается.

1. Задеплоить репозиторий на Vercel отдельным проектом (например,
   `storekmv-api.vercel.app`). Функция поднимется из папки `api/` автоматически.
2. Прописать переменные окружения — см. [DEPLOY-forms.md](DEPLOY-forms.md):
   `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `LEAD_TO`, `LEAD_FROM`.
3. Сверить адрес проекта с константой `LEAD_ENDPOINT` в `build-tilda.py`. Если домен
   другой — поправить константу и пересобрать блоки.
4. Кросс-доменные запросы разрешены только для storekmv.ru (список в `api/lead.js`,
   переопределяется переменной `LEAD_ALLOWED_ORIGINS`).

Проверка после деплоя:

```bash
curl -X POST https://storekmv-api.vercel.app/api/lead \
  -H 'Content-Type: application/json' \
  -H 'Origin: https://storekmv.ru' \
  -d '{"name":"Тест","phone":"+70000000000","consent":true}'
# ожидается {"ok":true} и письмо на LEAD_TO
```

Пока функция не задеплоена, формы будут показывать ошибку отправки. Сообщение об
успехе выводится только после ответа сервера, поэтому «молчаливой» потери заявок не
произойдёт.

## Шаг 5. Аналитика

Яндекс.Метрика подключается в настройках сайта Tilda (Настройки → Аналитика).
Код страницы при успешной отправке формы вызывает
`ym(window.YM_ID,'reachGoal','lead_submit')`, поэтому в блок T123 перед основным
кодом нужно добавить номер счётчика:

```html
<script>window.YM_ID=НОМЕР_СЧЁТЧИКА;</script>
```

В Метрике создать цель `lead_submit` (тип: JavaScript-событие).

## Как вносить правки потом

Править **исходники в репозитории** — `index.html`, `pages/*.html`, — затем
`python3 build-tilda.py` и заново вставить содержимое изменившегося файла в блок T123.
Правки, сделанные прямо в редакторе Tilda, потеряются при следующей сборке.

## Если понадобится уйти с Tilda на свой хостинг

Репозиторий к этому готов: страницы самодостаточны, функция форм лежит в `api/`,
`robots.txt` и `sitemap.xml` на месте. Нужно будет задеплоить репозиторий целиком на
Vercel, перевести DNS и очистить `LEAD_ENDPOINT` в `build-tilda.py` — тогда формы
пойдут на относительный `/api/lead`.
